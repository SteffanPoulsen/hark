# Roadmap

Ideas that have been weighed and kept, with the case that would make each one worth building. None of these is scheduled.

- **Send-to commands, the extension point.** A user-defined command line that runs on an exported or clipped file, with placeholders for the path and the range, off by default. That is how a DAW with a CLI or a script hook imports directly, and how Wwise or FMOD take a file through their APIs by way of a script, without hark learning any of them or growing a plugin ABI. The library tools do this per DAW, sensing the open session and spotting into it, which is the case that makes the feature worth building; a real plugin system only if commands prove too thin.
- **Channels are picked per file, not per preset.** Which channel of a source to keep (one mic of a pair, the good side of a dual-mono file with a dead side, channel 3 of a six-channel take) is a decision about that file, made beside the selection. Folding to mono is the project's output rule. The pick moves off the export card onto the waveform, where it acts on audition and export alike and is carried in the origin, and the preset keeps only whether to fold and how. A sound designer using hark looked for the channel pick and found it in the export settings, where a per-file choice does not belong.
- **Reverse as a selection edit.** A reversed swell or impact is a choice made when picking the sound, and taking a file to a DAW for one operation with no parameters is the round trip hark exists to save. It belongs with the fades: applied in audition and export, and recorded in the origin. The line it draws: operations without parameters that shape what is picked belong in hark, and parametric processing (pitch, EQ, time stretch) stays in the DAW.
- **Tabs in the file browser.** Each tab holds its own location, search and filter, so a few standing views (this project's favorites, every `ui` whoosh, the folder being worked through) sit one key apart instead of being rebuilt by hand. A sound designer asked for it in use. It also gives saved searches a home without a separate feature. The list gets a tab strip above it, and the tree and the filter act on the active tab.
- **The filter as a panel, tags made where they are used.** The filter's one long list becomes a wide panel: Favorites above, a column each for Tags, File type and Channels, and Clear below. A tag is a name and a colour, so it can be created at the moment it is applied, from the file's menu, while Settings stays where tags are managed. A sound designer new to hark could not find where tags come from.
- **List queries off the UI thread.** The folder list is one SQLite query on the window's thread; a root folder of 50,000 files takes about a fifth of a second to materialise, and a filtered view far less. The worker already opens its own database for scans, so a list job with a generation counter to drop stale results is the shape when a real library makes the root click hitch. That would also let the 2,000-row cap on text search go.
